# End-to-end test

```
env -C /private/tmp claude -p "Run the end-to-end test in /Users/james/workspace/claude-code/plugins/superpowers-github/tests/e2e/run.md: read that file first, then follow it exactly." --setting-sources project,local --plugin-dir /Users/james/workspace/claude-code/plugins/superpowers-github --model sonnet --max-budget-usd 3 --permission-prompts none --no-session-persistence --output-format json --allowedTools "Read(//Users/james/workspace/claude-code/plugins/superpowers-github/tests/e2e/run.md)" "Read(//private/tmp/superpowers-github-e2e-*/**)" "Edit(//private/tmp/superpowers-github-e2e-*/**)" "Bash(gh image check-token)" "Bash(date:*)" "Bash(ls:*)" "Bash(git clone https://github.com/trackness/superpowers-github-e2e-*)" "Bash(cd /private/tmp/superpowers-github-e2e-*)" "Bash(cd /private/tmp)" "Bash(git rev-parse:*)" "Bash(git status:*)" "Bash(git switch:*)" "Bash(git add:*)" "Bash(git commit:*)" "Bash(git -C /private/tmp/superpowers-github-e2e-*/clone push -u origin HEAD:main)" "Bash(git -C /private/tmp/superpowers-github-e2e-*/clone push -u origin e2e-work)" "Bash(gh repo view:*)" "Bash(gh repo list:*)" "Bash(gh repo delete trackness/superpowers-github-e2e-*)" "Bash(gh issue view:*)" "Bash(gh issue list:*)" "Bash(gh issue delete https://github.com/trackness/ideas/issues/*)" 'Bash(gh pr create -R trackness/superpowers-github-e2e-* --base main --head e2e-work --title "feat: add the greeting" --body-file /private/tmp/superpowers-github-e2e-*/files/pr-body.md)' "Bash(gh pr view:*)" "Bash(gh pr merge * -R trackness/superpowers-github-e2e-* --squash --delete-branch)" "Bash(gh project view:*)" "Bash(gh project list:*)" "Bash(gh project item-list:*)" "Bash(gh project item-delete 7 --owner trackness --id *)" "Bash(gh project delete * --owner trackness)" "Bash(rm -rf /private/tmp/superpowers-github-e2e-*)" "Bash(rm -rf /tmp/superpowers-github/*)" "Bash(rmdir /tmp/superpowers-github)"
```

This one command runs [run.md](run.md) unattended against real GitHub, as trackness. A headless Sonnet session starts in `/private/tmp` and loads this checkout of the mod. It leaves out the user settings, so no user hooks, plugins or auto-mode classifier take part. With `--permission-prompts none`, only the mod's own eleven tools (the mod allows them when no rule decides) and the commands listed in `--allowedTools` can run; anything else is denied and appears in the JSON output's `permission_denials`. Each GitHub write is allowed only in the shape run.md writes it: pushes and the PR pinned to the run's clone or repo, card deletion to the ideas board by its number, 7 (change it if that board is ever recreated). A board's number isn't known in advance, so board deletion is pinned only to the owner, and run.md checks the board's title before deleting it. A rule's `*` matches any characters, spaces included, so the rules keep a session to the script; they don't fence in one that sets out to break it. The session creates a private repo `trackness/superpowers-github-e2e-<timestamp>` and its board, clones the repo under `/private/tmp`, and calls every tool, asserting each result against GitHub. Along the way it opens and squash-merges a PR and waits for the issues to reach Done, and it moves one throwaway idea out of `trackness/ideas`. Then it deletes the repo, the board, the clone and the files it added to the mod's `/tmp/superpowers-github`, checks that none of them is left, and prints a PASS/FAIL report in the JSON `result` field, with the run's cost in `total_cost_usd` (about $0.60 with Sonnet; the $3 budget leaves room for teardown). It needs `gh image check-token` to print `trackness`. It leaves nothing behind, but per GitHub's docs the owner can restore a deleted repo for a while (90 days). If the run is cut short, for example by the budget, its teardown never runs: delete the leftovers yourself with `gh repo delete trackness/<name> --yes` and `gh project delete <number> --owner trackness`.


This one command runs [workflow.md](workflow.md): the workflow as a user drives it, against real GitHub, as trackness. A headless Sonnet driver session starts in `/private/tmp` and loads this checkout of the mod. It creates a private repo `trackness/superpowers-github-e2e-<timestamp>` and its board with board_setup, clones it under `/private/tmp`, installs superpowers into the clone at project scope (`claude plugin install superpowers@claude-plugins-official --scope project`), and commits the clone's `.claude/settings.json`, a `CLAUDE.md` and a README. A throwaway Haiku probe started in the clone then checks that it sees the superpowers skills from `…/superpowers/7.0.0/`. The driver then talks to an inner headless Sonnet session in the clone as a scripted user. The opening turn (`claude -p '<text>' --session-id <uuid>`) asks for superpowers:brainstorming and gives the whole design of a one-file project (a `VERSION` file holding `1`, planned as one task). Every later turn (`claude -p '<reply>' --resume <uuid>`) is a fixed reply from workflow.md's table, picked by what the session asked. In the passing run there were three: `The design is approved.`, `Yes.` (to "should we start?") and `Merge the PR.`. Before each reply the driver asserts what has landed on GitHub. After brainstorming, the parent issue is in Designed with the design as its body. After writing-plans, the parent has a `## Plan` section and a `Task 1` sub-issue in Todo. After subagent-driven-development and finishing, both issues are In Review, the task's commit is on the pushed branch, and there is a PR whose `pr_check` passes. After the merge, both issues are closed and in Done. Then the driver tears everything down, checks for leftovers, and prints a PASS/FAIL report in the JSON `result` field. It needs `gh image check-token` to print `trackness`, because design_write uploads the idea as `idea.md`.

The inner session runs with `--setting-sources project,local`, so no user settings, hooks or user-installed plugins take part: superpowers comes only from the clone's project scope, and the mod only from `--plugin-dir`. The subagents it dispatches share its permissions. Its allow rules are in [workflow-settings.json](workflow-settings.json), passed with `--settings`, which still applies under `--setting-sources project,local`. They allow the superpowers skill files, file edits in the clone, and the `git` and `gh` commands the skills run: pushes to `origin`, `gh pr merge` only with `--squash --delete-branch`, and deletion only inside the clone's run folders. A call they don't allow is denied and appears in that turn's `permission_denials`, which the driver lists in its Notes. A command with `&&`, `;`, a subshell, `$?` or a line break can't match any rule, so the clone's `CLAUDE.md`, which every session and subagent reads, asks for one command per Bash call and for multi-line text through files (`--body-file`, `git commit -F`). The driver's own rules pin each command to the run's paths. Its two inner-turn rules leave only the session id and the single-quoted turn text open. As in the test above, `*` matches any characters, so the rules keep a session to the script but don't fence in one that sets out to break it. `BASH_DEFAULT_TIMEOUT_MS` keeps a long inner turn in the foreground; a command that outlives its timeout is moved to the background, and the session is woken when it ends.

The passing run took 9.6 minutes and cost $1.63. The driver cost $0.57 (`total_cost_usd`). The inner session cost $1.05 with its subagents (its last turn's `total_cost_usd` is cumulative, and the report quotes it), and the probe cost $0.005. The $5 budget caps the driver only; each inner turn has its own `--max-budget-usd 15`.

Teardown does the following, then checks that none of it is left and that the boards, `trackness/ideas` and the user-scope plugins are as they were at the start:

- It uninstalls the project-scope superpowers with `--keep-data`, because the plugin's data folder is shared with the user-scope install. The install's entry in `~/.claude/plugins/installed_plugins.json` goes with it.
- It purges the inner session's transcripts (`claude purge`).
- It deletes the sessions' background-task folder under `/private/tmp/claude-501/`, the repo, its board (deleting a repo does not delete its board), the clone, and the files the run added to the mod's `/tmp/superpowers-github`.

Claude Code leaves an empty `~/.claude/session-env/<session id>` folder for each of the three sessions, as it does for every session, and won't let a session delete it. The report names the inner session's and the probe's folders, and the driver's folder is its own `session_id`. Remove them yourself if you want to.

If the run is cut short, its teardown never runs. Delete the leftovers yourself: from the clone, run `claude plugin uninstall superpowers@claude-plugins-official --scope project --keep-data` and `claude purge -y <clone>`; then run `gh repo delete trackness/<name> --yes`, `gh project delete <number> --owner trackness`, and `rm -rf /private/tmp/<name> /private/tmp/claude-501/-private-tmp-<name>-clone`.
