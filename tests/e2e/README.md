This one command runs [run.md](run.md) unattended against real GitHub, as trackness. A headless Sonnet session starts in `/private/tmp` and loads this checkout of the mod. It leaves out the user settings, so no user hooks, plugins or auto-mode classifier take part. With `--permission-prompts none`, only the mod's own eleven tools (the mod allows them when no rule decides) and the commands listed in `--allowedTools` can run; anything else is denied and appears in the JSON output's `permission_denials`. Each GitHub write is allowed only in the shape run.md writes it: pushes and the PR pinned to the run's clone or repo, card deletion to the ideas board by its number, 7 (change it if that board is ever recreated). A board's number isn't known in advance, so board deletion is pinned only to the owner, and run.md checks the board's title before deleting it. A rule's `*` matches any characters, spaces included, so the rules keep a session to the script; they don't fence in one that sets out to break it. A deletion rule has no `*` at all, since there it would also match a second path: the run works in one fixed folder, `/private/tmp/superpowers-github-e2e-run`, which its rule names exactly, and run.md stops at preflight if an earlier run left that folder behind. The mod's temp folder, `/tmp/superpowers-github`, whose entries are named by tool call ids no rule can know in advance, is cleaned by one fixed command: the run first writes `/private/tmp/superpowers-github-e2e-run/started`, and teardown runs `find /tmp/superpowers-github -mindepth 1 -newer /private/tmp/superpowers-github-e2e-run/started -delete`, which deletes what was made there after that file and keeps what was there before (an entry another session makes there during the run goes too). No rule deletes an issue in `trackness/ideas`, whose number isn't known in advance: if idea_move fails, the throwaway idea stays there, and the report lists it with the `gh issue delete` command. The session creates a private repo `trackness/superpowers-github-e2e-<timestamp>` and its board, clones the repo into that folder, and calls every tool, asserting each result against GitHub. GitHub can take a moment to show a write, so a read that checks one is re-checked for up to 60 seconds before it fails; a write is never repeated. Along the way it opens and squash-merges a PR and waits for the issues to reach Done, and it moves one throwaway idea out of `trackness/ideas`. Then it deletes the repo, the board, the clone and the files it added to the mod's `/tmp/superpowers-github`, checks that none of them is left, and prints a PASS/FAIL report in the JSON `result` field, with the run's cost in `total_cost_usd` (about $0.60 with Sonnet; the $3 budget leaves room for teardown). It needs `gh image check-token` to print `trackness`. It leaves nothing behind, but per GitHub's docs the owner can restore a deleted repo for a while (90 days). If the run is cut short, for example by the budget, its teardown never runs: delete the leftovers yourself with `gh repo delete trackness/<name> --yes`, `gh project delete <number> --owner trackness` and `rm -rf /private/tmp/superpowers-github-e2e-run`, and, if the idea is still in `trackness/ideas`, `gh issue delete <its URL> --yes`. The report's last line removes the session's empty folder under `~/.claude/session-env` (see [Session folders](#session-folders)).

This one command runs [workflow.md](workflow.md): the workflow as a user drives it, against real GitHub, as trackness. A headless Sonnet driver session starts in `/private/tmp` and loads this checkout of the mod. It creates a private repo `trackness/superpowers-github-e2e-<timestamp>` and its board with board_setup, clones it into the fixed folder `/private/tmp/superpowers-github-e2e-workflow/clone` (so the rules that delete the run's folder, its transcripts and its background-task folder each name exactly one path, as in the test above), installs superpowers into the clone at project scope (`claude plugin install superpowers@claude-plugins-official --scope project`), and commits the clone's `.claude/settings.json`, a `CLAUDE.md` and a README. A throwaway Haiku probe started in the clone then checks that it sees the superpowers skills from `…/superpowers/7.0.0/`. The driver then talks to an inner headless Sonnet session in the clone as a scripted user. The opening turn (`claude -p '<text>' --session-id <uuid>`) asks for superpowers:brainstorming and gives the whole design of a one-file project (a `VERSION` file holding `1`, planned as one task). Every later turn (`claude -p '<reply>' --resume <uuid>`) is a fixed reply from workflow.md's table, picked by what the session asked. In the passing run there were three: `The design is approved.`, `Yes.` (to "should we start?") and `Merge the PR.`. Before each reply the driver asserts what has landed on GitHub, re-checking a read for up to 60 seconds before it fails. After brainstorming, the parent issue is in Designed with the design as its body. After writing-plans, the parent has a `## Plan` section and a `Task 1` sub-issue in Todo. After subagent-driven-development and finishing, both issues are In Review, the task's commit is on the pushed branch, and there is a PR whose `pr_check` passes. After the merge, both issues are closed and in Done. Then the driver tears everything down, checks for leftovers, and prints a PASS/FAIL report in the JSON `result` field. It needs `gh image check-token` to print `trackness`, because design_write uploads the idea as `idea.md`.

The inner session runs with `--setting-sources project,local`, so no user settings, hooks or user-installed plugins take part: superpowers comes only from the clone's project scope, and the mod only from `--plugin-dir`. The subagents it dispatches share its permissions. Its allow rules are in [workflow-settings.json](workflow-settings.json), passed with `--settings`, which still applies under `--setting-sources project,local`. They allow the superpowers skill files, file edits in the clone, and the `git` and `gh` commands the skills run: pushes to `origin`, `gh pr merge` only with `--squash --delete-branch`, and deletion only of the run folder `.superpowers/sdd/1` (the parent is issue 1 in the new repo), named exactly. A call they don't allow is denied and appears in that turn's `permission_denials`, which the driver lists in its Notes. A command with `&&`, `;`, a subshell, `$?` or a line break can't match any rule, so the clone's `CLAUDE.md`, which every session and subagent reads, asks for one command per Bash call and for multi-line text through files (`--body-file`, `git commit -F`). The driver's own rules pin each command to the run's paths. Its two inner-turn rules leave only the session id and the single-quoted turn text open. As in the test above, `*` matches any characters, so the rules keep a session to the script but don't fence in one that sets out to break it. `BASH_DEFAULT_TIMEOUT_MS` keeps a long inner turn in the foreground; a command that outlives its timeout is moved to the background, and the session is woken when it ends.

The passing run took 6.6 minutes and cost $1.77. The driver cost $0.65 (`total_cost_usd`). The inner session cost $1.11 with its subagents (its last turn's `total_cost_usd` is cumulative, and the report quotes it), and the probe cost $0.007. The $5 budget caps the driver only; each inner turn has its own `--max-budget-usd 15`.

Teardown does the following, then checks that none of it is left and that the boards, `trackness/ideas` and the user-scope plugins are as they were at the start:

- It uninstalls the project-scope superpowers with `--keep-data`, because the plugin's data folder is shared with the user-scope install. The install's entry in `~/.claude/plugins/installed_plugins.json` goes with it.
- It purges the inner session's transcripts (`claude purge`).
- It deletes the sessions' background-task folder under `/private/tmp/claude-501/`, the repo, its board (deleting a repo does not delete its board), the clone, and, with the same fixed `find` as the test above against `/private/tmp/superpowers-github-e2e-workflow/started`, what was made in the mod's `/tmp/superpowers-github` during the run.

The report's last line removes the three sessions' empty folders under `~/.claude/session-env` (see [Session folders](#session-folders)).

If the run is cut short, its teardown never runs. Delete the leftovers yourself: from `/private/tmp/superpowers-github-e2e-workflow/clone`, run `claude plugin uninstall superpowers@claude-plugins-official --scope project --keep-data` and `claude purge -y /private/tmp/superpowers-github-e2e-workflow/clone`; then run `gh repo delete trackness/<name> --yes`, `gh project delete <number> --owner trackness`, and `rm -rf /private/tmp/superpowers-github-e2e-workflow /private/tmp/claude-501/-private-tmp-superpowers-github-e2e-workflow-clone`.

## Session folders

Claude Code makes an empty `~/.claude/session-env/<session id>` folder for every session, a headless one included, and won't let a session delete it. Each test's report ends with a `Cleanup:` line that removes the folders of the sessions it started: run.md's own session, and workflow.md's driver, inner session and probe. Resumed turns and subagents make no folder of their own: a passing workflow run left exactly those three. For example:

```
bash ~/workspace/claude-code/plugins/superpowers-github/tests/e2e/cleanup-session-env.sh <session id> <session id> <session id>
```

[cleanup-session-env.sh](cleanup-session-env.sh) runs `rmdir` on `~/.claude/session-env/<session id>` for each id it is given, and prints each folder it removes. `rmdir` removes only an empty folder, so it never deletes data, and the script skips any argument that isn't a session id.
